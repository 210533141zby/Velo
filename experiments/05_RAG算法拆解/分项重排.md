# 分项重排

这份说明只讲论文里的“分项重排”，并且直接按论文口径来写。

## 1. 它在论文里的位置

分项重排发生在共享检索主干之后，也就是：

`Dense + BM25 -> RRF -> Rerank -> 分项重排 -> 覆盖取证 -> 按题作答`

这里一定要注意，分项重排不是重新替代 `Rerank`，而是`以精排结果为底座做保守修正`。

## 2. 论文公式

论文公式 2-1 为：

`S_reorder(d)=0.70×R_base(d)+0.16×A(d)+0.10×C(d)+0.04×D(d)`

其中：

1. `R_base(d)`：共享检索主干经过 `Rerank` 后的基础相关性分数；
2. `A(d)`：文档对问题多个语义分项的覆盖情况；
3. `C(d)`：文档对整道问题整体词项的覆盖程度；
4. `D(d)`：时间、数字、专名、范围限定等高价值细节信号。

这组权重表达的核心意思很明确：  
`精排结果仍然占主导，分项信息只是做修正。`

## 3. 它到底解决什么问题

复杂问题通常不是只问一个点，而是同时要求多个方面。例如既问结论，又问原因，还问影响。如果继续只按单一相关性排序，头部证据很容易只覆盖其中一个方面，模型后续就会围着那个方面展开，最后表现成“答了很多，但还是漏项”。

因此，分项重排解决的不是“最后留哪几条证据”，而是：

`哪些文档或证据应该先排到前面，让模型先读到更贴题、更均衡的内容。`

### 4.2 公式里的量在代码里怎么找

| 论文符号 | 代码里看哪里 | 说明 |
| --- | --- | --- |
| `R_base(d)` | `build_document_reorder_breakdowns()` 里的 `rerank_score_norm` | 来自共享检索主干 `Rerank` 的基础相关性分数，经归一化后进入论文公式 |
| `A(d)` | `build_document_reorder_breakdowns()` 里的 `aspect_coverages` 和 `aspect_coverage` | 先拆问题分项，再统计每篇文档对各分项的窗口级覆盖情况 |
| `C(d)` | `build_document_reorder_breakdowns()` 里的 `overall_coverage` | 文档代表性窗口对整道问题的整体覆盖度 |
| `D(d)` | `build_document_reorder_breakdowns()` 里的 `detail_signal` | 时间、数字、专名等细节强度 |
| `S_reorder(d)` | `build_document_reorder_breakdowns()` 里的 `reorder_score` | 直接按论文权重算出的保守聚合分数 |

## 5. 代码里怎样直接找到论文公式

现在可以直接按下面这条链路去讲：

1. 在 [m01_共享检索主干.py](/root/Velo/experiments/05_RAG算法拆解/m01_共享检索主干.py) 里，`rerank_documents()` 先给出 `Rerank` 基础分；
2. 在 [m02_分项重排.py](/root/Velo/experiments/05_RAG算法拆解/m02_分项重排.py) 里，`build_document_reorder_breakdowns()` 明确算出 `R_base(d)`、`A(d)`、`C(d)`、`D(d)`；
3. 同一个文件里的 `rerank_documents_by_paper_formula()` 再按 `0.70 / 0.16 / 0.10 / 0.04` 计算 `S_reorder(d)` 并返回新的文档顺序；
4. 在 [m05_主流程串联.py](/root/Velo/experiments/05_RAG算法拆解/m05_主流程串联.py) 里，`_apply_paper_reorder_stage()` 把这一步接回整条主流程。

如果老师追问“为什么说是以精排结果为底座”，
最直接的证据就是 `rerank_documents_by_paper_formula()` 里 `0.70 * R_base(d)` 这一项仍然占主导权重。

## 6. 和覆盖取证的边界

分项重排只负责：

`谁先排前面`

它不负责：

`最后从这些候选里到底留哪几条`

后者属于覆盖取证，要看 [覆盖取证.md](/root/Velo/experiments/05_RAG算法拆解/覆盖取证.md:1)。
